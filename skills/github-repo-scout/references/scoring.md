# 评估矩阵

本文件是分类、评级锚点和 Gate 解释的唯一文字来源；结构化字段合法性、推荐资格和顺序由 `validate-decision` 执行。本矩阵只比较“通过”或“有条件通过”的候选。

不计算总分。每个维度使用 `strong`、`adequate`、`weak`、`unknown`，避免没有锚点的数字制造虚假精确性。

## 评级锚点

| 维度 | strong | adequate | weak | unknown |
|---|---|---|---|---|
| 需求适配 | 核心场景和主要约束均有直接证据支持 | 核心场景成立，次要约束存在可接受缺口 | 只能解决相邻问题或需要显著改造 | 未验证关键能力 |
| 成本类型 | `permanent_free`，或额度足够且确定周期重置的 `recurring_free_tier` | 周期免费额度可满足当前用量，但上限或超限处理需要管理 | `one_time_trial`、必须付费续用，或违反免费硬门槛 | 官方价格、额度周期或商用条款未核验 |
| 维护状态 | 最近提交样本含核心代码、测试、依赖或发布物的有效更新 | 成熟稳定，核心更新频率与项目阶段相符 | 最近样本只有 `non_core`，或长期无核心发布 | 样本仅媒体变更、缺少提交文件、release 或 Issue/PR 证据 |
| 安全与信任 | 依赖、安装入口、权限和数据边界已审查且无阻塞项 | 无已知阻塞项，但存在可明确缓解的非关键未知 | 存在高权限、隐蔽下载、不可接受遥测或供应链风险 | 未读关键 manifest、脚本或数据路径 |
| 证据与文档 | README、源码、发布物和官方资料相互印证 | 主要结论有一手证据，少量细节仅有项目方说明 | 关键主张与源码冲突，或文档明显过期 | 主要依据搜索摘要或无法访问的材料 |
| 采用与社区 | 多个独立信号表明持续采用和贡献 | 有真实使用者或贡献者信号，但规模有限 | 只有单一热度信号或生态薄弱 | 没有可核验采用信号 |
| 集成可行性 | 配置、迁移、运维和退出成本低且清楚 | 成本可控，有明确缓解与回滚方案 | 需要重度改造、专有服务或高退出成本 | 尚未核验部署和退出路径 |

Stars 只属于“采用与社区”的一个信号，不能单独形成 `strong`。

## 置信度

- **高**：所有影响结论的维度都有一手证据，关键主张已交叉核验。
- **中**：核心结论有一手证据，但仍有非关键 `unknown`。
- **低**：任一关键维度为 `unknown`，或主要证据来自维护者主张。

## 决策规则

1. 需求适配为 `weak` 或 `unknown`：不推荐。
2. 用户要求长期免费时，`one_time_trial`、`paid` 或 `unknown` 不得列为首选；`recurring_free_tier` 必须提供官方成本 URL 和重置周期，推荐 Gate 固定为 `conditional`，并通过 `validate-decision`。
3. 平台访问路线按 `permitted`、`permitted_with_conditions`、`separate_contract_required`、`prohibited`、`unknown` 分类；普通 API 审批和 OAuth 属于可有条件推荐，另签合同、禁止或未知则淘汰。
4. 可执行项目的安全与信任为 `weak`：淘汰；为 `unknown`：最多有条件推荐。
5. 维护状态不得由 `updated_at`、`pushed_at` 或文档提交单独判定；优先使用 `activity_summary`、提交文件和 release。
6. 其余候选依次比较需求适配、安全与信任、成本类型、维护状态、集成可行性、证据与文档。
7. 采用与社区只在前述维度相近时用于破同分。
8. 最终结论同时报告各维度评级和置信度，不压缩成一个总分。
